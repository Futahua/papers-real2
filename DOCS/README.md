# Papers REAL2 — Documentation

This is the authority for the Papers rebuild. Code serves these docs, not the
reverse. When code and a governing doc disagree, the doc wins.

## Structure

### `PROMPTER/` — governing founder & proxy docs (highest authority)

Read these first, in this order, at the start of any Papers session:

1. **`PAPERS_FOUNDER_BRIEF.txt`** (V3) — what Papers fundamentally is; the
   non-negotiable worldview (Backpacks, shared Tools, global AI, truthful
   grounding, world-layer-not-app). This outranks all repo history.
2. **`PAPERS_PROMPTER_HANDOFF.txt`** — the role a fresh session must assume
   (founder's product/technical proxy) and what to do first.
3. **`PAPERS_PROXY_OPERATING_MANUAL.txt`** — how to behave consistently across
   sessions; the Core / Contingent / Mistaken classification system; the
   authority chain.
4. **`PAPERS_SESSION_CLOSEOUT_PROTOCOL.txt`** — how to preserve a session's
   conclusions into durable docs before a chat reset.
5. **`PAPERS_AGENT_CONSTITUTION_V1.txt`** — binding operating constitution for
   coding agents on the rebuild: what they may infer, what they must never ask the
   founder, the engine-seam rule, world-first persistence, the truthfulness law,
   and the audit's dispositions as binding context. Downstream of the founder
   brief and the audit.

### Operational docs (this folder)

- **`PAPERS_REPO_DECISION_AUDIT_V1.txt`** — the Core/Contingent/Mistaken audit
  of legacy Papers v0 (REAL) plus the rebuild recommendation. Downstream of the
  founder brief; does not outrank it.

## Documents still to be written (per the prompter handoff)

- **`PAPERS_NEXT_BUILD_ORDER`** — the sequenced definition of the smallest
  non-generic Papers slice to build first.
- **`PAPERS_DELTA_LOG`** (optional) — lightweight cumulative record of changes to
  the docs over time.

## Documentation discipline (inherited as law from the v0 audit)

- One canonical context; do not spawn competing "final"/"latest"/"new" docs.
- Label statements with status: Vision / Confirmed decision / Current behavior /
  Partial / Prototype / Placeholder / Open question / Deferred / Superseded /
  Rejected. Never claim "working"/"complete"/"verified" without stating the evidence.
- Separate intention from evidence. Preserve uncertainty rather than freezing a
  guess into permanent design.
- No secrets in any doc.
