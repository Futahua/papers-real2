2026-07-09 (seventh pass) — the Desk: first inhabited Backpack slice
================================================================================

First active-work experiment inside a Backpack — a step past "Backpack as
persistent container with memory" into active work. Branch backpack-desk.
Concept doc: DOCS/PAPERS_BACKPACK_DESK_V1.txt (new, indexed).

WHAT WAS BUILT
1. THE DESK (rooms/<id>/desk.json — Papers-owned, durable): the Backpack's
   active work surface, distinct from its broader contents.
   - THE BRIEF: creator's current focus in their own words (identity =
     description; current work = brief). Edited inline; changes are events.
   - DESK ITEMS: ordered set of things/notes placed on the Desk; on/off the
     Desk without moving anything in the Backpack; membership changes are
     refs-carrying events. Detaching a thing prunes it from the Desk.
   - THE WORKING NOTE: one durable artifact (kind "working-note") the AI
     revises IN PLACE from the Desk. Same object across revisions;
     provenance.revisions[] records engine, brief used, and sources per
     revision; artifact-level sources always reflect the current text.
2. DESK-GROUNDED ASSISTANT: the AI's serialized context now carries a
   "THE DESK" block (brief + items with live status + working note) marked
   as its default working context — replies are grounded in active work,
   not in an undifferentiated dump. New Backpack-native guarded action:
   SYNTHESIZE THE DESK → working note. Preview and execution share one
   material-gathering path, so the preview is exact by construction.
3. UI: "The Desk — active work" section between the landing overview and
   the inventory; brief editing; Put on the Desk / Take off affordances on
   things and notes; working-note card with revision count; missing desk
   things shown missing on the Desk itself.

VERIFIED
- 25/25 unit tests (desk continuity/order/dedup, validation, detach prune,
  working-note in-place revision trail, Desk context serialization,
  synthesis prompt honesty).
- scripts/verify-desk.js LIVE on ollama end-to-end: brief + desk →
  synthesis → working note with full provenance → reality changed → second
  synthesis revised the SAME artifact (2-revision trail, no note pile) →
  restart continuity → missing-reality honesty on the Desk.
- Headed render with populated Desk clean.

ACCEPTED LIMITATIONS / DEFERRED
- Local qwen model ignored the TITLE line in synthesis; honest fallback
  title "Working note" used. Cosmetic; better models title properly.
- One working note per Backpack (deliberate first form — see concept doc).
- Desk state is not yet consulted by the world view's room cards.

================================================================================

The creator issued a binding vocabulary correction: Backpacks are the core
Papers-native organizing unit; the world is the real machine-and-life

1. New governing doc PAPERS_ONTOLOGY_CLARIFICATION_V1.txt.
2. All user-facing UI copy now says Backpack (creation flow, landing,

   history" / "Backpack conversation", identity line, pin labels, guard

2026-07-09 (fifth pass) — room history becomes a navigable room timeline
================================================================================

PR #2 merged. This pass deepens the room's accumulated life: room history
goes from a flat 8-line tail of prose to a navigable, honest timeline, and
the room's event record itself gets richer. Branch slice2a-room-timeline.

AUDIT FINDINGS THAT DROVE IT (from the merged code)
- Events were lossy prose: {kind, text, at} only — nothing connected an
  event to the note or thing it was about.
- WORST: refreshThings silently flipped things between present and missing
  with NO activity record. The room's most important truth — losing contact
  with reality — never entered the room's narrative.
- Only the last 8 events were visible; older history was persisted but
  unreachable in the UI.
- previousEnteredAt existed but history had no visit boundary.
- No path from an event back into the work it described.

WHAT WAS BUILT
1. EVENT REFS (data): activity events now optionally carry refs
   ({noteId, title} and/or {thingId, path, displayName}). All writers
   updated: attach/detach, note created, pin/unpin. Events without objects
   (room-created, renamed, described) carry none. Old pre-refs events are
   rendered as plain lines — no pretense of context that does not exist.
2. REALITY-TRANSITION EVENTS (truthfulness): refreshThings now logs
   'thing-missing' ("Lost contact with X — nothing at <path>") and
   'thing-recovered' ("X is back at <path>") when a thing's status actually
   changes — once per transition, never per refresh. Reality drift is now
   part of the room's story.
3. ROOM TIMELINE (UI): the history section renders newest-first, grouped by
   day (Today / Yesterday / date), with a "your last visit" divider placed
   where it truthfully falls, kind-coloring (lost contact red, recovered
   green, note-work accent), and a show-all/show-fewer toggle over the full
   persisted record (previously capped at 8 forever).
4. EVENTS AS PATHS BACK INTO WORK: an event about a note offers "open note"
   (or says honestly that the note is gone); an event about a real thing
   offers "open real location" (honest refusal if reality moved on) and
   says when the thing is no longer attached to the room. The
   since-your-last-visit landing block uses the same navigable rows.

CONSIDERED AND REJECTED: logging note *views* as activity (surveillance-ish
feed theater — activity records work, not attention); any separate "feed"
store (refs live on the same activity.json events).

VERIFIED: 19/19 unit tests (refs durability across restart; missing/
recovered logged exactly once; no refs on object-less events); live ollama
acceptance walk re-passed with a new check that losing contact produces a
refs-carrying room event; headed render of an aged real room (3 things,
1 genuinely missing, pinned note, 2 since-visit events) clean.

ACCEPTED LIMITATIONS
- Pre-refs events from earlier worlds render as plain text lines (honest).
- Timeline day-grouping uses the machine's local sense of "today" against
  UTC-stored timestamps; day labels can be off near midnight. Cosmetic.
- 'unknown'-status transitions are not evented (only present<->missing).

2026-07-09 (fourth pass) — Slice 2A begins: the room greets you with its state
================================================================================

Slice 1 was merged to main (PR #1). This pass is the first Slice 2A room-work
milestone, creator-directed: make entering a room feel like arriving in a
place with accumulated work, before any message is sent.

WHAT WAS BUILT (branch slice2a-room-landing)

1. ROOM OVERVIEW (landing block, top of room contents). Derived entirely from
   persisted world data at render time — never an ephemeral AI claim:
   - creator-owned room description (see 2)
   - honest snapshot line: N things (M missing) · N notes · N room events
   - missing-reality callout naming the things the room has lost contact with
   - "Since your last visit (<date>)" — real room events that happened
     between the previous visit and now, or an honest "nothing new"
   - notes pinned to the room, shown as cards on the landing

2. ROOM DESCRIPTION — durable creator-owned room state on the room record
   (room.json: description, descriptionUpdatedAt), edited inline, labeled
   "room description, yours · updated <date>". Changes are room events.
   Deliberately creator-written, NOT AI-synthesized: an AI-written room
   state block was considered and deferred — it would be a new guarded
   action class and needs its own staleness/provenance treatment.

3. VISIT MEMORY — room.json now keeps previousEnteredAt (shifted on every
   entry), which is what makes "since your last visit" honest rather than
   decorative.

4. NOTE PINNING — pinned/pinnedAt live on the artifact record. Pin/unpin
   from cards or the open note; pinning is a room event. Pinned notes live
   on the room landing; the shelf below lists the rest newest-first
   (previously oldest-first — revisitation was backwards). Notes created
   since the previous visit carry a "new since your last visit" badge.

5. WORLD VIEW CARDS carry more room life: description snippet, missing-thing
   warning, and the room's latest activity line.

6. DEV/TEST AFFORDANCE (not a product surface): PAPERS_OPEN_ROOM=<id|first>
   opens straight into a room; renderer logs room-render facts for headless
   verification.

DATA SHAPE: all new state lives in existing Papers records (room.json fields,
artifact fields, activity events). No new stores, no migration needed —
missing fields on old records read as absent and render honestly.

VERIFIED: 17/17 unit tests (visit memory, description trail, pin durability/
idempotence, world-card surfacing); live acceptance walk re-passed end-to-end
on ollama after all changes; headed render of a seeded real room (real repo
files, genuine AI note via ollama, pinned) rendered clean.

ACCEPTED LIMITATIONS / DEFERRED
- The "since your last visit" populated variant is unit-covered but was
  rendered with zero events in the headed check (truthful quiet variant).
- AI-written room-state synthesis deferred (see 2).
- "Reopen into the last room you were in" (app-level continuity) was noted
  as a real product question and deliberately not decided this run.
- Room history section itself unchanged (still last 8 quiet lines).

   (app/scripts/verify-slice1.js) walks build order §9 minus native UI steps.

   - default claude-cli: all Papers-owned checks passed; AI path reported an

2026-07-09 (second pass) — Slice 1 audit: room rebalanced away from chat
================================================================================

A hard audit of the first Slice 1 commit found early chat-drift seeds and
truthfulness flaws. Fixed before building further:

1. LAYOUT: the conversation was a fixed always-open panel at ~45% of the
   room — workbench geometry. Now the room contents (things, notes, history)
   are the primary full-width surface; the conversation is a fixed 340px,
   visually quieter, tuckable region. Its collapsed/open state is remembered.

2. TRUTHFULNESS: the renderer used to inject unpersisted "status" entries
   (e.g. open-a-missing-thing errors) into the conversation view, which
   presents itself as the persistent room record. Transient errors now render
   inline, visibly outside the record.

3. ROOM EVENTS BELONG TO THE ROOM: "note created" / "note failed" no longer
   post into the conversation. New Papers-owned room activity record
   (rooms/<id>/activity.json, append-only): room created/renamed, thing
   attached/detached, note created/failed. Displayed as a "Room history"
   section — the room visibly accumulates a life. (This pulls a small piece
   of Slice 2A forward; scoped to a plain record + quiet list, no cards or
   status machinery.)

4. NOTES ARE ROOM OBJECTS: notes now open as an in-room surface (breadcrumb
   back to room contents), not a modal popup. Note cards show body snippets.
   The guard/approval dialog remains a modal (appropriate for approval).

5. ROOM IDENTITY: header now carries "A room in this world since <date> ·
   N things · N notes" under the title.

6. BUGFIX: Escape while renaming a room committed the rename anyway; now it
   cancels.

Verified: 9/9 tests (new: room history survives restart, no-op renames log
nothing), smoke boot, headed render clean. The smoke world created in the
first pass reloaded with the same world id — live cross-restart continuity
observed, not just unit-tested. Live AI output still awaits `claude /login`.

KNOWN ACCEPTED GAP: the guarded note action reads thing content twice
(preview, then create) — if a file changes in between, the note reflects
reality at create time, which is the more truthful of the two; noted here so
it is a decision, not an accident.

WHAT CHANGED

   - Papers-owned world store: human-legible JSON under %APPDATA%\Papers\world
     (override: PAPERS_WORLD_DIR). Layout: world.json, rooms/<id>/room.json,
     things.json, conversation.json, artifacts/<id>.json. The store is the
     system of record; no engine transcript holds continuity.

   - Room-note artifacts: durable, provenance-carrying (createdBy: papers-ai,

     machine").

   - One engine seam: app/engine/adapter.js, calling the locally installed

- File-backed JSON world store, not SQLite. The world is deliberately
  inspectable on the real machine. Revisit only if scale demands it.
- Engine = local Claude Code CLI print mode. Thinnest possible engine
  configuration (build order §6.1): sign-in belongs to the engine's own
  tooling, not to any Papers surface. No provider UI exists anywhere.
